# 参赛演示视频脚本

## 成片要求

- 文件格式：MP4，分辨率 1920×1080。
- 总时长：5–8 分钟；建议控制在约 6 分 30 秒。
- 必须包含至少 2 分钟真实的 AI 协同过程复现。展示实际 Prompt、AI 回复、人工修改意见和代码落地/核验过程。
- 产品功能演示与 AI 协同过程放在同一条成片中。产品动图 `demo.gif` 只作预览，不能代替提交视频。
- 录制前关闭 `.env`、密钥、个人消息和不相关窗口。不要在屏幕上展示任何 API Key。

## 建议分镜（约 6 分 30 秒）

| 时间 | 内容 | 画面与讲解 |
|---|---|---|
| 0:00–0:25 | 问题与目标 | 展示一条模糊的比赛通知，说明信息核验、个人匹配和备赛计划为什么要串成一个流程。 |
| 0:25–0:50 | 产品与架构 | 展示四个 Agent 节点、规则层与最终报告，交代工具提供核验线索，不替用户认定赛事真假。 |
| 0:50–1:55 | 可疑通知 | 选择「可疑赛事」样例，展示抽取到的收费/保过话术、红色风险提示和下一步核验动作。 |
| 1:55–2:55 | 正常通知 | 选择「公众号推文」样例，展示字段证据、白名单命中、匹配度、分阶段计划，并导出 Markdown 报告。 |
| 2:55–3:25 | 信息不足与无关内容 | 依次展示「群聊消息」和「无效内容」，说明相对时间会保留为未知，非赛事内容会短路后续节点。 |
| 3:25–3:55 | 复现与评测 | 展示复现指南的 `npm ci`、`npm run dev` 和本地健康检查；快速浏览已有 12 条评测结果，并说明样本局限。 |
| 3:55–6:25 | AI 协同过程（至少 2 分 30 秒） | 打开实际 AI 工具中的原始会话，呈现至少 3 个核心功能迭代：完整 Prompt、AI 方案/代码、人工反馈或纠错、对应提交/代码和实际验证。至少讲清一次真实 Bug 的定位与修复。 |
| 6:25–6:30 | 总结 | 回到报告页，用一句话收尾：从零散通知到有证据、可核验、适合自己的参赛决策。 |

## AI 协同片段的取材要求

优先从开发时实际使用的 AI 对话中选取下列迭代：

1. 四节点流水线与 SSE 事件契约。
2. 原文 evidence 校验或风险评分规则。
3. 前端流程状态、报告展示或复现样例。

每段都应看得到完整上下文：

1. 人输入的需求和约束；
2. AI 给出的方案或代码；
3. 人对方案的取舍、补充要求或指出的问题；
4. 修改后的结果，以及对应的 Git 提交或运行界面。

不要把过程日志摘要、后补的旁白或静态幻灯片剪成仿造的 AI 对话。仓库的 `process-log.md` 是回顾材料，不是原始会话导出。若原始会话仍可访问，录制时直接打开真实会话；若不可访问，应先如实标记缺失并补录新的真实迭代，不要声称新录制内容是历史记录。

## 录制准备

- 浏览器缩放 100%，录屏分辨率 1920×1080。
- 启动项目后先访问 `http://localhost:5173`，确认顶部显示「演示数据」。
- 产品演示使用四个预置样例；演示模式不会调用外部模型。若展示实时模型，需先确认 `.env` 中已配置模型并在画面上隐藏密钥。
- 暂停通知，关闭终端历史中可能出现的密钥和个人路径。
- 鼠标移动放慢；每个样例等流程结束后再切镜头。
- 成片检查 MP4 编码、1080p、5–8 分钟时长和至少 2 分钟 AI 协同片段。
