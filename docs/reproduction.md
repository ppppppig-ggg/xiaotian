# 10 分钟复现指南

适用于 Windows 10/11、macOS 或 Linux 的本地演示。默认演示不需要模型密钥或外网 API。

## 环境要求

- Node.js 20 或更新版本；项目当前依赖 Vite 8、React 19 和 TypeScript 7。
- Git 与 npm。
- 浏览器可访问本机的 `5173` 端口。

## 从干净目录启动

以下命令以 PowerShell 为例：

```powershell
git clone https://github.com/ppppppig-ggg/xiaotian.git
Set-Location xiaotian
node --version
npm --version
Copy-Item .env.example .env
```

打开 `.env`，保持 `USE_MOCK=true`。演示模式不需要填写 `LLM_API_KEY`，也不会把输入发送给模型服务。

```powershell
npm ci
npm run dev
```

首次安装依赖可能需要数分钟。两个服务启动后保持该终端运行：

- 前端：<http://localhost:5173>
- 后端健康状态：<http://localhost:8787/api/health>

健康状态应包含 `"ok":true` 和 `"mode":"mock"`。

## 现场演示顺序

1. 点「公众号推文」，再点「开始分析」：查看赛事字段、可展开的原文证据、风险结论、匹配度和备赛计划。
2. 点「导出报告」：浏览器下载一份 Markdown 决策报告。
3. 点「可疑赛事」：确认红色风险项和手动核验步骤。
4. 点「群聊消息」：确认“下周三”保留为相对时间，不会被演示模式猜成具体日期。
5. 点「无效内容」：确认后三个节点跳过，并在报告中说明没有识别出赛事。

演示模式只接受界面中的四个预置样例。手动修改文本会取消预置样例状态，并禁用演示分析按钮，避免把固定回放误认为模型对自定义文本的判断。

## 切换到实时模型

仅在确实需要展示自定义文本分析时启用：

1. 在 `.env` 设置 `USE_MOCK=false`。
2. 配置模型服务的 `LLM_API_KEY`、`LLM_BASE_URL` 和 `LLM_MODEL`。
3. 重启 `npm run dev`，确认界面顶部显示「实时模型」。

实时模式会将粘贴的赛事文本发送至 `.env` 配置的模型服务。录屏时隐藏 API Key，并避免粘贴含个人隐私的群聊内容。

## 常见问题

| 现象 | 处理 |
|---|---|
| 页面显示「服务未连接」 | 确认 `npm run dev` 启动成功；后端默认端口为 8787。 |
| `npm ci` 报 Node 版本不满足 | 安装 Node.js 20 或更新版本后重新打开终端。 |
| 演示模式无法分析自定义文本 | 这是预期行为；选择一个预置样例，或按上节配置实时模型。 |
| 报告还显示上一条结果 | 修改文本或选择另一个样例会重置旧结果；点击开始后等待工作流结束。 |
| 实时模型请求失败 | 核对模型服务商提供的 Base URL、模型名和 Key；保持 `USE_MOCK=true` 仍可演示固定样例。 |

## 可选的本地质量检查

在项目目录另开终端执行：

```powershell
npm run build
npm run lint
```

`eval/report.md` 保存了仓库现有的 12 条自建评测记录。它用于回归说明，不代表真实赛事信息的准确率，也不代替评审时对最新代码的独立复核。

重新生成该报告需要启动 `USE_MOCK=false` 的后端和可用的模型服务；批量评测会调用模型并消耗额度。当前仓库报告是在本轮风险规则修改之前生成的，提交前应在实际配置下重新运行并替换报告。
